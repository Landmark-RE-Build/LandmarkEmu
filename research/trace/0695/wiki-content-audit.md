# Wiki content vs the server (agent #9, 2026-10-15)

Every content page of the fandom dump (design/wiki: the trace/0695/wiki-xref.tsv kinds prop, creature, outfit, weapon,
tool, consumable, resource, pet and goal) against what LandmarkEmu has: is the thing in the server's data, can a player
get it the way the wiki says, and do the goals exist, fire and reward. Read-only audit; scripts and full per-page
output in `re/out/agent_wiki/` (data.py loaders, sources.py = every server item source emulated from the code,
audit.py → content.tsv, goals.py → goals.tsv + objectives.tsv, gen.py → this file). Re-run them after server changes.

**Sources.** Server: LandmarkEmu/LandmarkEmulator.WorldServer (Game/*.cs, cited file:line), its data (gameData =
the 0.589 client tables the server reads; gameData/items.json = the 44-CommandBase item dump; Resources/PacketDumps
71-AchievementBase = the live goal capture, 145-PropBase = prop models). Client: 0.589 / 0.695 text (re/out/text_589.tsv,
text_695.tsv), 0.695 tables (<0.695 install>). Wiki: design/wiki/pages (file per page; pages cited by title, file =
title with `\/:*?"<>|` → `_`). Other agents' results used, not redone: items-695.md (#7), launch-rules-audit.md (#4),
trace/systems/crafting-meta.md (progression deep trace 10-14).

**Verdicts.** *present & obtainable*: in the server data and a player can get it by a route the wiki names (crafting
at a reachable station with known recipe and obtainable components, gathering, drops, goal rewards, starter kit,
or — for props — placing it from the palette with its knowledge and cost satisfied). *present not obtainable*: in the
data, no working route (the free Showcase store, Store.cs:162-209, is listed but never counted as the wiki route).
*wrong*: the server's own logic contradicts the wiki (e.g. lets everyone place a prop the wiki and the live data say
must be discovered). *missing*: nothing of that name (after fuzzy matching) in the dump, PropDefs or client text.
*client-only*: the client has the name (0.695 PropDefs / text) but the server has no item / prop / goal row.
*not applicable*: overview / class / list pages, pre-launch code items. **Wiki numbers that differ from the client's
own tables** (recipe counts, outputs, prop costs, innate flags) do not change the verdict: the server uses the
client's launch tables (0.589 exe 2016-06-04), which are developer data and beat the wiki (BUILD-PATH rule; the wiki
mixes beta and post-launch values). They are listed in the `notes` column of content.tsv and summarised in §2.9.

Main findings:

1. **Items and props mostly work.** 1,454 of 1,575 content pages are present and obtainable the wiki's way; 70 pages
   matched only after fuzzy / alias matching (wiki typos, word order, renames such as Gray → Grey, Drowners → Drowner's).
2. **13 props that a "Recipe:" item grants are free for everyone** (wrong): the dump's grantId names the prop, but
   RecipeBook links recipe items by name (RecipeBook.cs:37-75), so 5 teach a dead crafting recipe instead and 8 are not
   linked; KnowsProp (RecipeBook.cs:85-98) then lets anyone place them (§2.8, gap 5.8).
3. **The Getting Started chain stalls at its first goal**: 5 of its objectives are counted by no code (track a goal
   in the Journal, place a campfire, Like a gallery site, visit another player's site, fire the grappling hook), so
   471 → 480 → 478 → 477 → 685 cannot finish and Becoming a Luminary never starts (§3.4, gap 5.5).
4. **28 tier-2/3 combat goals (and 13 other tiers) have no definition**: the capture holds only tier 1; the next tier
   was added later by the live server (client AchievementAdd, sub 2, FUN_142d92750 case 2, which the server never sends).
   Slayer of All the Things, There Can Be Only One and 17 title items can never be earned (§3.3, gap 5.6, L42).
5. **Learning a prop recipe never counts a goal**: LearnProp (RecipeBook.cs:185-204) skips Achievements.RecipeLearned —
   307 objectives (303 Recipe Discoveries, Winter is Coming) can never complete (gap 5.7).
6. **Meta goals are linked by text**, which fails for 11 objectives whose child exists (8 "… complete" without d,
   "Weeping in the Willows" for 496 Weeping Willow, "Always Like Going South" for 524 Trees With Beards?, "The Bigger They
   Are …") although the capture carries the objective → child map (gap 5.9). About 90 further goal objectives
   (placing N faction characters, linking, tinting, biome props, creature unlocks, emote challenges, Lost Crystal
   reached…) have no trigger (gap 5.10); the wiki's "Other Information" gives the trigger for most (goals.tsv `hint`).
7. **Pets, event outfits and 0.695 props are client-only**: 6 pet figurines, 12 event / pre-launch outfits, 22 fireworks
   emitters — already TASKS 4.8-4.17 (#7); not repeated as gaps.
8. **VISIBILITY_REQUIREMENT_ID is not an achievement id** (answer to #7's hand-off): 512 of 513 values that fall on
   capture ids name an unrelated achievement; TRACKER_ACHIEVEMENT_ID is (186 / 186 name-match the "Replicator" list
   achievements, which nothing counts — L43).

## 1. How each page was checked

- Matching: page title against item names (dump, 0.589 and 0.695 text), PropDefs names (0.589 and 0.695), then
  singular / plural, "(prop)"-style suffixes, word order, one extra word, difflib ≥ 0.88, the grantId of a "Recipe: <title>"
  item, 5 hand-checked aliases and 8 pages left *missing* with candidates (audit.py ALIASES / CANDIDATES).
- Wiki claims parsed per page: Innate yes / no (infobox or "This prop is innate"; the three "Innate … (List)" pages override
  a page that says No — 12 pages contradict their list), station, Lumen price, How To Make components and output,
  marketplace / drop / chest / goal mentions.
- Server routes (sources.py, each with its code citation): starter kit (Inventory.cs:58-66), ore veins (OreVeins.cs:48-52),
  ground digging (TerrainMaterials.cs:24,231-243), trees (Gathering.cs:105,149-153), plants (Gathering.cs:137-141, removed
  at launch: TASKS 6.12), gathering drops incl. random recipe items (Gathering.cs:30-52, RecipeBook.cs:127-133), creature
  loot (Creatures.cs:57-112,1414-1415), cave chests (LootChests.cs:176-185), outpost chest / Lost Crystal (Outposts.cs:417-490),
  bags and sets (ItemUses.cs), goal rewards (capture reward bundles, Achievements.cs:215-232,879-886), salvaging (station
  41), and crafting: a recipe counts when it is default-learned or taught by a linked recipe item, its station is reachable
  (Replicator at the Spire, Lumen Station UI, or a placeable station prop: Sifter, Rusty Workshop, Stone Forge, Rusty
  Salvager — CraftingStations.cs:23-64) and every component is itself obtainable (fixed point; 1,242 of 2,885 dump items).
- Props: model in 145-PropBase, KnowsProp (innate / learned), placement cost (PropDefs PROP_RECIPE_ID → components,
  Props.cs:1423-1461) obtainable.
