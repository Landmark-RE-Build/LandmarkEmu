# Settings Reference

> Generated by `tools/wiki_reference.py` from `.env.example`, the compose files in `docker/` and the
> `*Configuration.cs` classes. Edit those (or the script), not this page.

Every server program reads its settings from a JSON file next to the program (`WorldServer.json`, `AuthServer.json`
...; each project ships a `*.example.json` with every key), then from **environment variables with the same names**,
which override the file, then from the command line. A nested key is written with `__` in a variable
(`Network__Port`, `Database__Auth__ConnectionString`, `Admins__0`).

With Docker (see [Server Installation](Server-Installation)) you only edit **`.env`**: each compose file forwards a
`.env` line to the setting the program reads. The tables below give, for every `.env` line, the setting each service
receives (`service: Key`), the default, the value live Landmark used, and what it does.

- **Default** is the value `.env.example` ships with; the program and compose defaults are the same unless noted.
- **Live** is how the official servers behaved: `true` / a value when that is known from the game's sources, *not
  known* when no source says, and *—* for settings with no live counterpart (ports, passwords, our own extras).
  Every gameplay setting defaults to live behaviour; extras beyond live are off.
- Settings marked *(commented out)* are written `#NAME=value` in `.env.example`: remove the `#` to use one.

## Network

### `PUBLIC_HOST`

The address players on OTHER PCs use to reach this PC.

- empty: this PC only (127.0.0.1).
- your LAN IP for players on your home network.
- a VPN address (Tailscale, ZeroTier) or your public IP / host name for players elsewhere.

The world server tells every game this address, so it must be one they can reach.

| `.env` | Service setting | Default | Live |
|---|---|---|---|
| `PUBLIC_HOST` | world: `PublicAddress`<br>world: `WebPagesUrl` | (empty) | — |

### `LOGIN_PORT`

Ports. Players need all but DB_PORT open (Windows Firewall, and port forwarding on your router for players outside your home network). Each is published on the same port number inside the container, except ACCOUNT_PORT, which always maps to the auth container's port 5000. Login server (UDP): the game logs in here.

| `.env` | Service setting | Default | Live |
|---|---|---|---|
| `LOGIN_PORT` | auth: `Network__Port`<br>auth: published port | `20042` | — |

### `ACCOUNT_PORT`

Account service (TCP): LaunchPad and the website create accounts and log in here.

| `.env` | Service setting | Default | Live |

### `ADMIN_ACCOUNT`, `ADMIN_2`, `ADMIN_3`, `ADMINS`

The server's copy of the game's data tables (default server-data/gamedata, made by the setup service from GAME_DIR). It must be the players' client build: for 0.695 clients point it at a folder with the 0.695 tables.

| `.env` | Service setting | Default | Live |
|---|---|---|---|
| `GAME_DATA_DIR` *(commented out)* | auth: mounted folder<br>envserver: mounted folder<br>world: mounted folder | (empty) | — |

### `WORLD_DATA_DIR`

Where this world keeps its saved files, console.log (and the five runs before it, console.0.log newest.. console.4.log) and dev_commands.txt (default server-data/worlds/&lt;WORLD_KEY&gt;).

| `.env` | Service setting | Default | Live |
|---|---|---|---|
| `WORLD_DATA_DIR` *(commented out)* | envserver: mounted folder<br>world: mounted folder | (empty) | — |

### `ENVSERVER_DATA_DIR`

The Environment Server's data folder when it runs in its own container (ENVSERVER_ADDRESS above; default &lt;the world's data folder&gt;/envserver).

| `.env` | Service setting | Default | Live |
|---|---|---|---|
| `ENVSERVER_DATA_DIR` *(commented out)* | envserver: mounted folder | (empty) | — |

### `LAUNCHER_DIR`

LaunchPad's news file folder (default docker/launcher; the patch folder is PATCH_DIR above).

| `.env` | Service setting | Default | Live |
|---|---|---|---|
| `LAUNCHER_DIR` *(commented out)* | auth: mounted folder | (empty) | — |

### `NETWORK_NAME`, `WEB_SUBNET_PREFIX`

Docker network name and the website network's address range, if they clash with others on this PC.

| `.env` | Service setting | Default | Live |
|---|---|---|---|
| `NETWORK_NAME` *(commented out)* | auth: `name`<br>commerce: `name`<br>envserver: `name`<br>gateway: `name`<br>social: `name`<br>world: `name`<br>worldchannel: `name` | `landmarkemu` | — |
| `WEB_SUBNET_PREFIX` *(commented out)* | auth: `WebApi__TrustedProxy`<br>auth: network name / alias<br>auth: network range<br>project: network range | `172.30.77` | — |

## Settings without a .env line

These keys exist in the code but no `.env` line sets them: they keep their default under Docker unless you add the
environment variable to the service yourself (a `docker-compose.override.yml`), or set them in the JSON file when
you run a program without Docker.

| File | Key | Default | What it is |
