# Command Documentation

> Generated by `tools/wiki_reference.py` from `DevCommands.cs`, `Emotes.cs` and the lists in the script. Edit those,
> not this page.

LandmarkEmu has three kinds of commands:

1. **Player slash commands** that the server adds to the game client (`/who`, `/duel`, the emotes, `/membership`).
   Anyone can use them.
2. **The retail client's admin slash commands** (`/goto`, `/target`, `/hideme`, `/item`, `/servertime` ...). The client
   offers them only to a player the server marks as an admin, and the server checks again for every command: a
   non-admin's command (only a modified client could send one) is refused and logged. `/admin` opens the admin menu.
3. **Dev commands**: the world server's own command set (`Game/DevCommands.cs`), for running and testing a server.
   They are run from the server side, never typed in game chat (see below).

## Who is an admin

The world settings `ADMIN_ACCOUNT`, `ADMIN_2`, `ADMIN_3` and `ADMINS` (comma separated) name the admins (see
[Settings Reference](Settings-Reference#admin_account-admin_2-admin_3-admins)). Write each entry as
`account:<account name>` (every character of that account) or `character:<character name>` (that character, on
any account). A bare name still works for either, but is ignored while an account and another player's character
share it, so nobody can become admin by registering an admin's name in the other namespace. Admin rights are
per world: each world reads its own list. An admin sees "You are an admin: type /admin to open the admin menu." when
entering the world.

## Running dev commands

- **dev_commands.txt.** Append a line to `dev_commands.txt` in the world's data folder (Docker:
  `server-data/worlds/<WORLD_KEY>/dev_commands.txt`; without Docker, next to the world server program). The world
  reads the file about once a second, runs each line and empties the file. Lines starting with `#` are ignored.
- **The admin menu.** `/admin` in game → *Any command* runs a dev command for yourself, one player or everyone. The
  menu's buttons are dev commands too. Commands run on the next server tick and every run is logged with the admin's
  name; results appear in chat or in the world's log (`docker compose logs -f world`, or `console.log` in the data
  folder).
- **Targets.** A line without a prefix runs once **for every player online**; `@Name command` runs it for that
  character only. A few commands ignore the target (switches such as `propstream`, `pathing`), and `kick` must have
  an `@Name`.
- **Who may run them.** Anyone who can write to the world's data folder (the server owner), and admins through the
  admin menu. Treat both as full control of the server: dev commands can give items, move and remove players, run Lua
  in their game client and send them raw packets.
- Arguments in `<angle brackets>` are required, `[square brackets]` optional, `a|b` means one of them. Item, prop,
  recipe and other ids are the game's own ids (the client's data tables); `guid hex` values are as the server log
  prints them.

Example `dev_commands.txt` lines:

```
broadcast The server restarts in 10 minutes.
@Alice give 231 10
@Bob kick 30 Please read the server rules.
timeofday 12
```

## The other server programs

- **Login server console** (only when it runs in a terminal; Docker disables it): `account create <username>
  <password>` creates an account (the sign-up's rules apply: 3-32 letters, digits or underscores, a password of at
  least 6 characters; it works while sign-ups are closed). Players normally create accounts in LaunchPad or on the
  sign-up website (see [Account Creation](Account-Creation)).
- The social, commerce, gateway, world-channel and Environment Server programs have no commands; they are
  configured through their settings only.
