# Database Documentation

> Generated by `tools/wiki_reference.py` from the EF Core model snapshots and the services' SQL. Edit those, not
> this page.

LandmarkEmu keeps its data in **MariaDB / MySQL** (Docker runs MariaDB 11.4 in the `db` container; the database
port is published on the host PC only, `DB_PORT`, for tools like HeidiSQL). The programs create and update their
own tables at start:

- the auth, character, world and social databases through **EF Core migrations** (the `Migrations` folder of each
  `LandmarkEmulator.Database.*` project; applied history in each database's `__EFMigrationsHistory` table);
- the commerce and world-channel databases with plain `CREATE TABLE IF NOT EXISTS` statements, columns added later
  being added at start when missing.

Docker creates `lmemu_auth` and `lmemu_character` on the database container's first start and grants the
`landmarkemu` user the others (`docker/db-init/01-databases.sql`); each service creates its own database the first
time it starts. The connection strings are built by the compose files from `DB_PASSWORD` (see
[Settings Reference](Settings-Reference)); without Docker they are the `Database` keys of each program's JSON file.

| Database | Schema | Used by | Tables |
|---|---|---|---|
| [Auth](Database-Auth) | `lmemu_auth` | login server, worlds, gateways | 3 |
| [Character](Database-Character) | `lmemu_character` | login server, worlds | 31 |
| [World](Database-World) | `lmemu_world_<WORLD_KEY>` | its world | 9 |
| [Social](Database-Social) | `lmemu_social` | social service | 7 |
| [Commerce](Database-Commerce) | `lmemu_commerce` | commerce service | 14 |
| [World-Channel](Database-World-Channel) | `lmemu_wc_<WORLD_KEY>` | the world's world-channel service | 1 |

Keys and ids: character ids, item guids and prop guids are 64-bit numbers the server allocates; item, prop,
recipe and other *definition* ids are the game client's own ids from its data tables. World positions are in the
client's local metres unless a column says otherwise (build-site boxes are in decimetres).

Back up the database volume before upgrading the server or switching on an optional service with a one-time import
(see [Server Guide](Server-Guide)).
